# Local setup

Use a disposable DSH home for installation, persistence and removal tests. Do
not copy credentials, provider keys or private session logs into it, and never
point these steps at your everyday profile.

## Build and package

```bash
npm run verify     # build lib/client.js, unit tests, release gate
npm pack
```

The source of truth for the plugin page is `client/index.mjs`; `lib/client.js`
is generated by `npm run build`.

## Isolated installation

In a separate terminal (do not change the home of your active DSH process):

```bash
export DSH_HOME="$(mktemp -d /tmp/dsh-control-mcp-e2e.XXXXXX)"
dsh plugin --profile web add /absolute/path/to/dsh-control-mcp-0.1.0.tgz
dsh --profile web --no-open --port 18766
```

Use the URL it prints, not an assumed one. Starting this server does not update
your normal DSH GUI.

Replacing an installed tarball needs a restart of that test server.
`dsh plugin remove` uninstalls the package but leaves this entry's config row in
`$DSH_HOME/profiles/web/cordis.patch.yml`; delete the `dsh-control-mcp` row there
for a clean reinstall test.

## Browser test of the plugin page

```bash
DSH_E2E_URL='http://127.0.0.1:18766/?token=…' DSH_E2E_NARROW=1 npm run test:e2e
```

The script starts its own temporary headless Chrome profile and drives it over
CDP. It opens Plugins → Harness control, checks the bundle detail, turns MCP and
the API on from the page, checks the token section and snippets, read-only mode,
blocked-pattern validation and enforcement, persistence after reload, token
rotation, the narrow layout and console errors, then switches both surfaces
off again. Set `DSH_E2E_SHOTS=/some/dir` for screenshots. After uninstalling,
`DSH_E2E_ABSENT=1` checks that the page and routes are gone.

## Live MCP / API test

Turn MCP and the HTTP API on (the page, or the browser test without its final
step), copy the token from the page, then:

```bash
DSH_CONTROL_BASE=http://127.0.0.1:18766 DSH_CONTROL_TOKEN=dshc_… npm run test:live
```

It checks auth refusals, the MCP handshake, every curated tool, `dsh_call` and
`dsh_stream`, workspace and session creation and cleanup, API errors and the
SSE relay, and the stdio bridge as a real process. It creates a workspace in a
temporary directory and removes it again.

`DSH_SMOKE_NO_PROMPT=1` skips the one `session/prompt` round trip. Without it
the test sends one short prompt, which calls the configured model; a disposable
profile without a provider exercises the error path instead.

## Hooking a real client

Point an MCP client at the test server, for example Claude Code:

```bash
claude mcp add --transport http dsh-control-test http://127.0.0.1:18766/dsh-control-mcp/mcp \
  --header "Authorization: Bearer dshc_…"
```

Keep screenshots, browser profiles, test homes, tokens and logs out of Git and
the npm artifact (`.e2e/` is ignored). Stop the test server when done, and verify
a computed test-home path before deleting it.
